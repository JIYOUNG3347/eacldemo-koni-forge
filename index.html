System Demonstration

KONI-Forge

An LLM development platform built on four measurement-driven components: knowledge-boundary diagnosis, data augmentation, in-training safety monitoring, and confidence-based ensembling.

What you can try

Knowledge boundary diagnosis

Upload documents and measure how much of that knowledge the base model already holds — the measurement decides what happens next.

Routed pipeline

High coverage routes to retrieval; low coverage routes to fine-tuning. The route is derived from the measurement, not from a preset.

In-training monitoring

Benchmarks run between training rounds. A significant regression halves the learning rate or stops training and rolls back.

Agent orchestration

Seven specialist agents drive the stages through a shared state and a planner that selects the next step from that state.

Suggested path (about 15 minutes)

  1. Sign in and upload two or three English PDFs. Documents must be in English — the pipeline runs in English.
  2. Let the pipeline index them and run the boundary diagnosis. You will see a coverage percentage and the route it implies.
  3. Watch question generation, preprocessing, and training proceed. Each stage reports what it did, and what it skipped.
  4. Open the evaluation report. Layers that were not measured are marked as such rather than scored.
This is a live system on shared lab hardware. One GPU serves every visitor, so a training run started by someone else will queue yours behind it. Please keep runs small — the available models are 0.5B–1B parameters, which is what this hardware supports. Some features are disabled in the public build.
